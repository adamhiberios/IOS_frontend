**Method.** Static analysis only — no dev server, no runtime clicks. Every route was enumerated from the 13 `*.routes.ts` files; every page component was opened and each `inject(...)` followed to its data-access layer to confirm `HttpClient`/`socket.io` vs in-file fixtures; connectivity was built from an exhaustive sweep of `routerLink` / `router.navigate` / `navigateByUrl` (including dynamically-bound `[routerLink]` sources); i18n coverage was computed by extracting all `lang.t('…')` literals and diffing against `assets/i18n/{en,fr,ar}.json`. Where code and `docs/backend-analysis.md` / `docs/implementation-progress.md` disagree, **the code wins** and the discrepancy is noted.

## 1. Legend

### Data source

| Tag           | Meaning                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **REAL**      | Injects a `*Store`/`*Api` that calls `HttpClient` against `environment.apiBaseUrl` (or `wsBaseUrl`). Endpoints listed.  |
| **MOCK**      | Renders from hardcoded arrays/objects in the component or in a store that returns fixed data. Marker quoted.            |
| **MIXED**     | Some sections real, some mock/UI-only. Both named.                                                                      |
| **STATIC**    | Purely presentational marketing/legal copy; all text from `LanguageService.t()` + asset paths. No data layer by design. |
| **NAV-STATE** | Reads its entire payload from `Router` navigation `state` — nothing fetched, nothing persisted.                         |

### Functional status

| Tag            | Meaning                                                                     |
| -------------- | --------------------------------------------------------------------------- |
| **Functional** | Real backend wiring, complete round-trip per static analysis.               |
| **Partial**    | Real wiring for the main path, but a named sub-feature is unwired/disabled. |
| **Stub**       | Renders and accepts input, but the submit path performs no persistence.     |
| **UI-only**    | Renders; controls are bound to nothing that leaves the browser.             |
| **Blocked**    | Held back by a named backend gap (`BE-I-xx`).                               |
| **Demo-only**  | Static by design (marketing/legal) — correct as-is.                         |
| **Broken**     | Reachable but cannot work as reached (entry-flow defect).                   |

> **Global i18n note.** All three locale files (`en`/`fr`/`ar`, 2 509 keys each) are key-for-key identical — no locale is missing a key the others have. **Arabic is machine-translated and pending professional review**; this applies to the whole app and is not repeated per page. `LanguageService.t()` returns the raw key on a miss (`language.service.ts:47,53`), so missing keys surface as visible key strings rather than blanks.

### 4.5 Entry-flow gaps

1. **Slug-vs-UUID (highest severity).** `cert-detail.page.ts:411-417` sends `?count=`/`?time=` to a runner that reads only `?certId=`/`?attemptId=` (`mock-test.page.ts:379-397`). Result: an empty runner. The `:code` slug (`ESM-P`) is not a backend certificate id and is never resolved to one. Only `/courses/:certId` supplies the real UUID.
2. **Nav-state-only pages.** `/assessments/ready` and `/assessments/result/:sessionId` read their entire payload from `Router` navigation state. Refresh, back-button return, or a shared/bookmarked URL yields an empty page. `/assessments/result/:sessionId` even carries a `:sessionId` it never uses — the obvious fix is to fetch by it.
3. **Query-param dependencies without fallback.** `/dashboard/certificates/mock-test/result` needs `?attemptId=`; `/admin/lessons/:lessonId/quizzes` needs `?title=`; `/auth/new-password` needs `?token=`. Only new-password handles the missing case explicitly.
4. **`authGuard` drops query params from `returnUrl`.** It rebuilds from path segments (`auth.guard.ts:24`), so a deep link like `/dashboard/certificates/mock-test?certId=…` returns post-login as `/dashboard/certificates/mock-test` — an empty runner.
5. **`publicOnlyGuard` covers all of `/auth/*`** (`app.routes.ts:35`), so a signed-in user cannot reach `/auth/verify-email` or `/auth/complete-account`. Fine for verify-email (unauthenticated flow), fatal for complete-account if it is ever meant to run post-registration.
